# ТСД Telnet — telnet-клиент для терминала сбора данных

Клиент для складской системы на терминале сбора данных под **Android 4.0.4 (API 15)**.
Без внешних библиотек: только `android.*` из прошивки, поэтому приложение не тянет AndroidX
и работает на старых ТСД.

Пароли и «коды кнопок» берутся из текстового файла на карте памяти, приложение
перечитывает его перед каждым подключением — пересборка APK не нужна.

## Что где лежит

| Файл | Назначение |
|---|---|
| `MainActivity.java` | экран, меню, клавиши ТСД, приём сканера, переподключение |
| `TelnetClient.java` | сокет, два потока, переговоры telnet (IAC), автоответ на приглашения |
| `TelnetConfig.java` | разбор `/sdcard/telnet.ini`, создание шаблона, escape-последовательности |
| `AnsiParser.java` | разбор VT100/ANSI: CSI, цвета, очистка, альтернативный экран |
| `TerminalScreen.java` | сетка символов, курсор, область прокрутки, история (scrollback) |
| `TerminalView.java` | отрисовка сетки, цвета ANSI, прокрутка пальцем, псевдографика |
| `KeyMapper.java` | клавиша ТСД → байты на сервер, подмена и блокировка из конфига |
| `CharsetKit.java` | cp866 / windows-1251 / koi8-r / utf-8 |
| `LogKit.java` | лог в файл на карте памяти (для разбора проблем на месте) |
| `telnet.ini` | пример файла настроек: `adb push telnet.ini /sdcard/telnet.ini` |

## Установка

```bat
:: 1. настроить адрес, логин, пароль — и на устройство
adb push telnet.ini /sdcard/telnet.ini

:: 2. установить приложение
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

APK: `app\build\outputs\apk\debug\app-debug.apk` (debug-подпись, ставится как обычно).
Собрано с `minSdkVersion 15`, `targetSdkVersion 33`, AGP 9.1.0 / Gradle 9.3.1 / JDK 21.

Если файла `/sdcard/telnet.ini` нет, приложение создаст его само с комментариями
и предложит поправить.

## Экран и управление

* Полноэкранный терминал + строка состояния внизу (`сервер | состояние | размер сетки | кодировка`).
* Клавиша **MENU** (или долгое нажатие по экрану) — меню: подключить, отключиться,
  перечитать настройки, показать настройки, экранная клавиатура, шрифт, кодировка,
  диагностика ввода, о программе.
* **Шрифт крупнее / мельче** — подгонка размера букв прямо на месте. В режиме
  `auto_size=1` «крупнее» означает меньше колонок; приложение печатает готовые строки
  `min_cols`/`min_rows`, их достаточно вписать в файл, чтобы размер сохранился.
* **Кодировка: следующая** — перебор `cp866 → windows-1251 → koi8-r → utf-8` прямо на
  месте, с переподключением. Удобно подбирать кодировку, не правя файл; в файле значение
  не меняется (после перезапуска — снова из `/sdcard/telnet.ini`).
* **Диагностика ввода** — включает «режим ревизии»: на экран выводятся коды нажимаемых
  клавиш ТСД (`код`, `meta`, `unicode`) и содержимое рассылок сканера. Нужна, чтобы точно
  подобрать коды клавиш для `[keys]` и параметры сканера под конкретную прошивку.
* Клавиша **BACK** — закрыть соединение, повторное нажатие закрывает приложение.
* Проведение пальцем — прокрутка истории; короткое нажатие — вернуться вниз.
* Экранная клавиатура — через меню: появляется строка ввода, Enter отправляет набранное.
* Экран не гаснет, пока приложение открыто.

## Конфигурация

Полный пример — в `telnet.ini`. Основное:

```ini
[server]
host=192.168.0.10      ; адрес сервера
port=23                ; порт
charset_recv=cp866     ; кодировка приёма: cp866 / windows-1251 / koi8-r / utf-8
charset_send=cp866     ; кодировка отправки (обычно та же)
auto_connect=1         ; подключаться при запуске
auto_reconnect=1       ; восстанавливать связь при обрыве
nodelay=1              ; не копить символы — важно для интерактивных меню
lf_as_crlf=1           ; сервер присылает только LF — вернуть каретку
enter=CR               ; что отправлять на Enter: CR / LF / CRLF

[auth]
login=user             ; логин из файла
password=change_me     ; пароль из файла
prompt_login=login:    ; приглашение сервера, после которого отправляется логин
prompt_password=Password:
prompt1=Код склада:    ; любые дополнительные пары «приглашение → ответ»
answer1=01
send_on_connect=0      ; 1 — отправить логин/пароль сразу после подключения
delay_ms=300           ; пауза перед ответом

[keys]
; только исключения, остальные клавиши уходят на сервер «как есть»
F1=\eOP                ; подмена: F1 → ESC O P
VOLUME_UP=DISABLE      ; заглушить клавишу
BACKSPACE=\x08         ; изменить байт backspace
ENTER=CR               ; переопределить Enter

[scanner]
keyboard=1             ; сканер как клавиатура: штрихкод приходит как нажатия клавиш
intent=0               ; приём штрихкода broadcast-ом от iScan (для iData 95 — так надёжнее)
intent_auto=1          ; слушать рассылки iScan и при intent=0 (так работает «из коробки»)
intent_action=android.intent.action.SCANRESULT   ; action iData (ключ extra — value)
intent_extra=value     ; имя extra со штрихкодом
suffix=CR              ; что дописать после штрихкода (для intent-режима)

[screen]
auto_size=1            ; сетка под размер экрана
cols=80                ; при auto_size=0 — строгое число колонок
rows=24
min_cols=40            ; при auto_size=1 — сетка, которая обязана влезть
min_rows=12            ; меньше колонок = крупнее шрифт (40x12 обычно, 32x10 крупнее)
font_size=12
box_drawing=unicode    ; ascii — если шрифт не рисует псевдографику
builtin_font=1         ; встроенный моношрифт с кириллицей (DejaVu Sans Mono); 0 — системный
theme=dark             ; dark / light

[log]
enabled=1              ; лог в файл
data=1                 ; писать содержимое обмена (для отладки)
file=/sdcard/telnet.log
```

### Поддерживаемые в конфиге клавиши

Имена как в Android (`KEYCODE_F1`), без префикса (`F1`) или числовым кодом (`131`).
Значение — строка с escape-последовательностями: `\e`, `\r`, `\n`, `\t`, `\x1b`, `\033`,
либо слово `CR`, `LF`, `CRLF`, `TAB`, `ESC`, `NUL`. Слово `DISABLE` (или `ignore`, `none`, `off`)
заглушает клавишу.

### Что уходит на сервер по умолчанию

| Клавиша | Байты |
|---|---|
| печатные символы | сама буква/цифра в кодировке `charset_send` |
| Enter, центральная кнопка | значение `enter` (по умолчанию `CR`) |
| Backspace (DEL) | `0x7F` |
| Esc | `0x1B` |
| Tab | `0x09` |
| стрелки, Home/End, PgUp/PgDn, Ins | `ESC [ A/B/C/D`, `ESC [ H/F`, `ESC [ 5~/6~`, `ESC [ 2~` |
| F1–F4 | `ESC O P/Q/R/S` |
| F5–F12 | `ESC [ 15~` … `ESC [ 24~` |
| Ctrl+буква | управляющий код `0x01`…`0x1A` |
| MENU, SEARCH, модификаторы | не отправляются (меню приложения) |

## Настройка под iData 95 (iScan)

Сканер у iData обслуживает приложение **iScan**. Ему нужно указать, как отдавать
штрихкод другим программам:

**МЕНЮ → Настройки → Настройки сканирования → Дополнительно → Режим передачи
результата** (Scan results Send mode). Варианты:

* **Рассылка / Intent (Broadcast)** — рекомендуемый. В конфиге:
  `keyboard=0`, `intent=1`, `intent_action=android.intent.action.SCANRESULT`,
  `intent_extra=value`, `suffix=CR`.
* **Клавиатура / KeyEvent** — штрихкод приходит как нажатия клавиш. В конфиге:
  `keyboard=1`, `intent=0`. Обязательно включить в iScan суффикс/окончание
  **Enter**, иначе сервер не поймёт, что штрихкод введён до конца.

Дополнительно в iScan включите работу **в фоне**, иначе при активном нашем
приложении рассылка может не приходить.

Приложение принимает штрихкод тремя способами, независимо от `keyboard`/`intent`:

* отдельные нажатия клавиш (режим клавиатуры);
* весь штрихкод одним пакетом символов — тоже клавиатурный режим (`ACTION_MULTIPLE`);
* широковещательная рассылка по `intent_action` (при `intent_auto=1`, по умолчанию).

Режим **«Буфер обмена / Clipboard»** не читается — переключите iScan на «Рассылка».

Если рассылка не приходит или приходит с другими именами, включите в приложении
меню → **Диагностика ввода** и отсканируйте товар: на экране появится строка вида

```
рассылка сканера: action=android.intent.action.SCANRESULT extras{value=4600123456789, ...}
```

По ней видно реальные `action` и имя extra — их и вписывайте в `[scanner]`.
Можно перечислить несколько action через запятую, приложение подпишется на все.
Если вместо рассылки в диагностике мелькают нажатия клавиш («клавиша: KEYCODE_…»),
значит iScan работает в режиме клавиатуры — переключите на «Рассылка» либо
оставьте `keyboard=1` и настройте суффикс Enter в iScan.

### Клавиши ТСД

Физическая клавиатура iData 95 отдаёт обычные Android-коды. Какие именно коды
приходят на вашей прошивке, проще всего узнать так:

1. меню → **Диагностика ввода**;
2. нажать нужную клавишу ТСД;
3. на экране появится `клавиша: KEYCODE_… (код N), meta=…, unicode=…` — это имя и код для `[keys]`.

Например, если сервер ждёт ESC при нажатии F1, а ТСД шлёт свой код — впишите
строку `F1=\eOP` (или `131=\eOP`) в `[keys]`.

### Буквы и ромбики

* Если буквы выводятся **ромбиками/квадратиками** — сначала проверьте кодировку:
  меню → **Кодировка: следующая** и по очереди `cp866`, `windows-1251`, `koi8-r`, `utf-8`
  (после каждого приложение переподключается). Если при верной кодировке буквы всё равно
  ромбики — в системном моношрифте ТСД нет кириллицы; при `builtin_font=1` приложение
  рисует встроенным шрифтом с кириллицей, поэтому ромбиков быть не должно.
* Если **не вводятся буквы, а цифры вводятся** — в приложении есть запасное правило:
  когда карта клавиш прошивки отдаёт для буквы `unicode=0`, символ берётся прямо из кода
  клавиши (`A`…`Z`, `0`…`9`, пробел). Проверить, что приходит от клавиатуры, можно в
  диагностике ввода по полю `unicode`. Если у ТСД клавиатура только цифровая, буквы
  вводятся через экранную клавиатуру (меню → «Экранная клавиатура»).
* Если сервер ждёт русские буквы, а клавиатура отдаёт латинские — задайте нужные символы
  в `[keys]`, например `A=\x80` (буква «А» в cp866).

## Частые проблемы

| Симптом | Что делать |
|---|---|
| «Кракозябры» вместо текста | подобрать `charset_recv` меню → «Кодировка: следующая» или в файле (`cp866`, `windows-1251`, `koi8-r`, `utf-8`) |
| Кириллица ромбиками | встроенный шрифт (`builtin_font=1`) + верная кодировка |
| Буквы не вводятся, цифры вводятся | включить «Диагностику ввода» и посмотреть `unicode`; буквы подставляются из кода клавиши, для чисто цифровой клавиатуры — экранная клавиатура |
| Строки съезжают лестницей | `lf_as_crlf=1` (если сервер отдаёт только LF) |
| Меню шире экрана / обрезано | для строгих 80x24: `auto_size=0`, `cols=80`, `rows=24`; для широких меню — `auto_size=1` |
| Шрифт мелкий | меню → «Шрифт крупнее»; закрепить: уменьшить `min_cols`/`min_rows` (например, 32x10) или `auto_size=0` + `font_size` |
| Рамки из меню не видны (квадратики) | `box_drawing=ascii` |
| Приглашение логина не распознаётся | вписать точный текст в `prompt_login`/`prompt_password` (регистр не важен, пробелы сохраняются) |
| Сервер спрашивает что-то ещё | добавить пары `prompt1`/`answer1`, `prompt2`/`answer2` |
| Штрихкод не отправляется | `keyboard`: включить в iScan суффикс Enter; `intent`: включить в iScan режим «Рассылка/Intent» и проверить `intent_action`/`intent_extra` через меню «Диагностика ввода» |
| Сканер не вставляет данные | включите «Диагностику ввода» и отсканируйте: `пакет символов: "…"` — режим клавиатуры, `рассылка сканера: …` — режим Intent; тишина — iScan настроен на буфер обмена/другой action |
| Рассылка сканера не приходит | в iScan разрешить работу в фоне; проверить `intent_action` через «Диагностику ввода» |
| Непонятно, какой код у клавиши ТСД | меню → «Диагностика ввода», нажать клавишу — на экране будет имя и код |
| Символы ввода «залипают» порциями | `nodelay=1` |
| Нужно понять, что происходит | `[log] enabled=1`, `data=1` и посмотреть `/sdcard/telnet.log` |
| Приложение закрывается сразу при запуске | обновите APK: в сборках до 18.10.2026 у `TerminalView` не было конструктора для разметки. Если повторится — пришлите вывод `adb logcat -d -v time AndroidRuntime:E *:S` |

## Что проверено, а что нет

Проверено автотестами на JVM (90 проверок, все успешны): разбор конфига и
escape-последовательностей, эмулятор VT100/ANSI (позиционирование, цвета, очистка,
область прокрутки, альтернативный экран, перенос строки, история), кодировки,
раскладка клавиш, переговоры telnet (WONT/DO/WILL, NAWS, TTYPE), сквозной обмен
с локальным сервером — логин и пароль ушли из файла, экран собрался из принятого потока, —
а также проверка разметки: у собственных View есть конструктор `(Context, AttributeSet)`
и все `findViewById` ссылаются на объявленные id (иначе приложение падает при запуске).

Повторить проверку на ПК (устройство не нужно):

```bat
tools\selftest\run.bat
```

Скрипт компилирует Android-независимую часть приложения вместе с заглушкой
`android.view.KeyEvent` и прогоняет набор проверок. Полезно после правок в
`TerminalScreen`, `AnsiParser`, `TelnetClient`, `TelnetConfig`, `KeyMapper`.

Не проверено на реальном устройстве: отрисовка `TerminalView` (Canvas), реальные
клавиатуры и сканеры конкретных ТСД, поведение прошивок 4.0.4. Это проверяется
только установкой на терминал — тестовый прогон нужно делать на самом ТСД.
